# 技術スタック (Tech Stack)

本プロジェクト（Miiiwa Portfolio）で使用されている主要な技術・ライブラリの一覧です。

## コア・フレームワーク
- **Next.js 16** (App Router) - Reactフレームワーク。本プロジェクトの基盤。`output: 'export'` による静的サイトとして書き出す構成のため、サーバー機能は使用していない。
- **React 19** - ユーザーインターフェース構築ライブラリ。
- **TypeScript** - 静的型付け言語。安全で堅牢なコードベースの維持に使用。

## 3D表現・WebGL
- **Three.js** - ブラウザ上で3Dグラフィックスを描画するためのコアライブラリ。
- **@react-three/fiber** (R3F) - Three.jsをReactのコンポーネントとして宣言的に記述するためのラッパー。
- **@react-three/drei** - R3F用の便利なヘルパーライブラリ。本プロジェクトでは主に `CameraControls`（カメラ制御）、`Billboard`（常時カメラを向くラベル）、`useCursor`（ホバー時のカーソル変更）を使用。

## スタイリング・アニメーション
- **Tailwind CSS** (v4) - ユーティリティファーストのCSSフレームワーク。デザイントークンは `src/app/globals.css` の `:root` に集約。
- **Framer Motion** - React向けの高機能アニメーションライブラリ。セクションのフェードイン、詳細ページの開閉、モーダルの出現に使用。
- **Lucide React** / **React Icons** - SVGアイコンライブラリ。技術スタックのアイコンはローカル描画（外部CDNに依存しない）。

## 主な特徴的な実装（アーキテクチャ）
- **プロシージャル・ボクセル生成**: 外部のGLBモデルに依存せず、`InstancedMesh` と数式を用いて数千のブロックからなる街をパフォーマンスを維持したまま動的に生成。1モデル＝1ドローコール。
- **フォント→ボクセル変換**: 任意の文字列をオフスクリーンCanvasでラスタライズし、立体のボクセル文字へ自動変換（`voxel/text.ts`）。
- **ハイブリッド・レイアウト**: `<Canvas>` を背面（`-z-10`）に固定配置し、その上に通常のHTML/CSSで構成されたコンテンツをオーバーレイさせることで、3Dの没入感とWebサイトとしての情報伝達性を両立。
- **カメラモデル**: 島の周りを一定の半径で周回する1つのカメラ。行き先の判断は `Scene.tsx` の単一の effect に集約されており、経路は3つだけ（エリアへ寄る / ロゴで固定のホーム視点へ戻る / スクロールで離脱して全景に戻りつつそのエリアを正面に置く）。カメラの座標計算は `3d/worldLayout.ts` に純粋関数として切り出され、テストされている。
  - **飛行は `camera-controls` のダンピングではなく、自前の時計とイージングで回す。** 毎フレーム `glidePose(from, to, easeInOutCubic(t))` を組んで `setLookAt(..., false)` に渡す（焦点オフセットも同じ曲線で運ぶ）。`setLookAt(..., true)` の `smoothTime` は**出だしが最速**の臨界減衰で、`smoothTime` 経過時点で約59%進む。詳細ページから戻る飛行はシートが退く**0.3秒**のあいだ画面に映らないので、見えるようになった頃には終わりかけていた（＝「引く」ではなく「着地の残り」に見える）。対称なイージングなら 0.3秒 時点でまだ 9.4% しか進まない。
  - **飛行の長さは「押したボタン」ではなく「開始時に画面が覆われていたか」で決める**（覆われていれば 1.2 秒、そうでなければ 0.8 秒）。そのため `pageOpen` の前回値が要るが、行き先の effect は `pageOpen` では再実行させたくないので、**その effect の後ろに** ref 更新専用の effect を置いて宣言順で前後関係を保証する。
  - **飛行の補間は位置の線形補間ではなく注視点まわりの軌道**（`glidePose()`）。弧の2点を結ぶ直線は弦で、弦の中点は弧の内側に入る＝引いている途中で一度街へ近づく。`CameraControls.lerp()` は球面補間をしてくれるが、両端の方位を `atan2` で復元して生のまま引くため ±π をまたぐと長い方へ回る（回り続ける自己紹介から HOME を押すと起きる）。`wrapAngle()` を通すために自前にしている。
  - **飛行の初回フレームには `delta` を加算しない。** `delta` は前フレームからの経過であり、飛行は effect の中＝フレーム間で始まるので、その経過は飛行の時間ではない。詳細ページの裏は `frameloop="demand"` で毎秒1フレームなので、これを加算すると1フレームで飛行がほぼ終わる。クランプ（`MAX_FLIGHT_STEP`）は 1/10 の保険にとどめる — 1/30 にすると 30fps を下回る端末で飛行そのものがスローモーションになる。
  - `frameDistance()` は対象の外接球が収まる距離を、垂直・水平の狭い方の半画角から算出する（縦長ビューポートでも収まる）。`camera-controls` の `fitToBox` は内部でカメラ角度を90°刻みに丸めるため、斜め俯瞰のこのシーンでは使えない。
  - `facingSection()` が「今どのエリアが正面か」を方位角から決め、左のカードはこれを読むだけ。カードとカメラが互いを更新する双方向を避けている。**速度でゲートしない** — 回転が速いあいだ結果を凍結すると、島は回っているのにカード・ドットの強調・点線だけが画面外のエリアに貼り付く（実測: 1.5秒のフリック中にカードが1度も変わらず、最初の変化が2529ms後）。以前このゲートがあったのは「点線の遠端は瞬時に飛ぶのにドット側の強調がイージング中で、線が何も指していないように見える」ためだが、それはドット側（スポットライトだけイージングしない）で解消済み。
  - **ホームの右寄せは焦点オフセット（`setFocalOffset`）で、注視点は動かさない。** `homeFocalOffsetX()` が返す負の x で、カメラを自分のローカル右軸方向へ平行移動する。セクションが使う「注視点を横にずらす」手（`framePose` の `sideways`）はホームでは使えない: (1) 注視点は `rotateAzimuthTo()` の公転軸そのものなので、ずらすと軸が島の中心から外れ、一周する間に島が画面上を円を描いてふらつく。(2) `azimuthAngle` は `_spherical.theta`＝注視点から見たカメラの角度なので、ずらすと基準が定数ぶん回り `facingSection()` が隣のエリアを指す。焦点オフセットは `camera-controls` が軌道を組み立てた**あと**に適用されるため `_spherical` も `_target` も無傷。逆に、セクションへ寄るときは**明示的に 0 に戻す**（`framePose` 側の寄せと二重になる）。ずらし量はフレーム幅に対する割合なので、リサイズ時に再計算する。
  - **自己紹介だけ構図が違う**: 他のセクションはカードを避けるための浅い接近ショットだが、自己紹介はカードを持たない素のテキストなので、遠景・深い見下ろし角・大きめの右寄せ（`ABOUT_TILT` / `ABOUT_RADIUS` / `ABOUT_TARGET_Y` / `ABOUT_CARD_SHARE`、`worldLayout.ts`）で構図だけを変える。新しい effect は増やさず、唯一の effect の中で係数を差し替えるだけにしている。数値は `reference/image2.png` とのピクセル計測で決めており、**回転する被写体なので一周ぶんサンプリングした最悪角度で判断する**（島はタワーや看板のぶんシルエットが伸縮し、フレーム幅の 42〜47% と振れる。1枚のスクショだけで詰めると、広く見える角度で右端が見切れる）。
  - **自己紹介だけ静止しない**: 他のセクションは全画面シートが裏を覆うので視点が止まっていても気づかれないが、自己紹介はシーンがそのまま見えているため、着地後も `useFrame` 内でゆっくり回り続ける。回転の中心は `rotateAzimuthTo()`（今の注視点中心）ではなく、`distance`・`sideways`・方位角を `aboutOrbitRef` に保存し、方位角だけ進めて毎フレーム `framePose()` を再計算する方式 — 右寄せの注視点そのものを軸にすると被写体が画面内でふらつくため。
  - **回転の軸はホームと同じ島の中心**: 自己紹介の建物自身を軸にすると、その建物だけが静止点になり島の残りがその周りを回るという、他のどのビューとも違う回転になる。`target` は建物のバウンディング球中心ではなく `[0, ABOUT_TARGET_Y, 0]`（原点を通る垂直線＝ホームと同じ軸の上）を使う。**共有すべきなのは軸であって半径ではない**ので、`ABOUT_RADIUS` はホームと別の値を取れる（構図を決めるのはこちら）。`ABOUT_DISTANCE = ABOUT_RADIUS / cos(ABOUT_TILT)` は、傾けたぶんの斜辺を取って水平距離を `ABOUT_RADIUS` に保つための式。`ABOUT_TARGET_Y` を `HOME_TARGET_Y` より下げているのは、カメラは注視点を画面中心に置くため、狙いを下げると島が画面の上へ持ち上がるから（下げないと島の底面が下端で見切れる）。
- **エリアのマーカーと点線**: マーカーは WebGL のスプライト（深度バッファに乗るので建物に隠れる）、カードからマーカーへの点線は DOM の SVG（常に最前面の平面）。両者の受け渡しは購読チャンネル（`3d/markerScreen.ts`）経由で、React state を通さない（毎フレームの再レンダーを避けるため）。
  - **マーカーと点線は「招待状」で、フォーカスした時点で役目が終わる**: エリアにズームすると `activeSection` が立ち、**全マーカーが半径0**になり、点線とカード側のアンカードットも消える。カメラが着いた先を指し続けるものは要らないという一本の理屈で、自己紹介の特別扱いも不要になった。スポットライトのドットだけ「イージングしない」特例があるが、それは**入場方向にだけ**適用する（`isSpotlight && target > 0`）。退場にも適用すると、フォーカスした瞬間に自分のドットだけパチッと消える。
  - **カードは重ね（スタック）で、ホバー中のホイールでエリアを送れる**（`AreaCard.tsx` / `cardWheel.ts`）。後ろの2枚は中身を持たない板（見えるのは縁だけなので、中身を入れると読めないコピーに高さが縛られる）。ホイールは React の `onWheel` ではなく素の `addEventListener` で取る — React は root に**パッシブ**登録するので `preventDefault()` が効かない。`stopPropagation()` も必須で、無いと `Scene.tsx` の `window` ホイールに流れて**カードも送られ島も回る**。**1ジェスチャ＝1枚**に固定してあり、次の静止（220ms）までロックする。1歩ごとにカメラが回るため、一振りで3〜4エリア送ると指を離したあともカメラが回り続ける。フォーカス中は板も送りも引っ込める（カメラが駐まっていて軌道もロックされているので、送っても視界と違うカードになるだけ）。
  - **点線の起点は、作り直される要素の中に置かない。** アンカーの点はカードの角を印しているが、置き場所は**カードの中ではなくスタックのコンテナ**。カードは `AnimatePresence` で `key={section}` を持つため切り替わりのたびに作り直され、`popLayout` では退場側がしばらく残る。入場側が `anchorRef` をセットしたあとに退場側の ref コールバックが `null` で呼ばれると `anchorRef.current` が空になり、`draw()` が毎フレーム先頭で return して**線が最後の位置で凍る**（＝「線がドットからずれる」ように見える）。あわせて `draw()` はアンカーが無いとき return せず**線を消す**ようにしてある — 古い線が残るほうが悪い壊れ方だから。
  - **マーカーの大きさは world 単位ではなく画面 px で決める。** `markerScaleForScreenRadius()` が、そのスプライトのビュー深度から「指定した px 半径になるワールド scale」を毎フレーム逆算する。点線は線幅も間隔も画面 px で組まれているので、注釈の両端を同じ単位で持つことになり、線が点から取るべき距離が計算不要の定数になる。
  - 逆向き（world で持って画面 px を推定する）は成立しない。スプライトはビルボードで頂点を**ビュー空間**でずらすため、画面サイズは深度だけの関数で、俯角にも画面内の位置にも依存しない。ワールド鉛直ベクトルを射影して測ると俯角と遠近法の両方が混ざり、マーカーが画面を上下するたびに 3px 以上ぶれる。
  - テクスチャの充填率 `MARKER_DOT_FILL`（スプライト矩形に対する円の半径の比）は `worldLayout.ts` の定数で、テクスチャを描く側も距離計算もここを読む。
  - **射影の前に `camera.updateMatrixWorld()` を呼ぶ。** `camera-controls` の `update()` は毎フレーム `position` / `quaternion` だけを書き、行列を張り直すのは後段の `gl.render()`。これを挟まないと `.project()` が前フレームのカメラで射影し、キャンバスは今フレームで描くため、**動いている側だけ1フレームぶんズレる**（回転方向で離れ方と被さり方が反転する）。同一フレーム内の値どうしを突き合わせる検証ではこの種のズレは検出できない。
- **ジオラマの時計**: 自分から動くもの（観覧車・トラム・雲・住人・紙吹雪・マーカーの脈動・アイドル自動回転）は、レンダラの時刻ではなく `3d/sceneClock.ts` を読む。ヘッダーの停止ボタンはこの時計を凍らせるだけで、全部が同じフレームに止まる。停止していた時間は加算されるのではなく**割り引かれる**ので、再生は止めた瞬間の続きから始まる（位置が時刻だけの関数であるトラムと住人が瞬間移動しない）。停止中もカメラは手で回せる — ダンピングには実 delta を渡し、自動回転の加算だけこの時計を通しているため。
- **自己紹介の帰り道は「読み終えること」**（`aboutScroll.ts`）: 自己紹介だけは詳細シートを持たず、テキストが直接ジオラマの上に乗るため、他セクションのような「シートをスクロールで抜ける」帰り道が無かった。列自体をスクローラにして、下端（0.995）に達したらホームへ戻る。HOME ボタンは自己紹介では出さない。`scrollHeight - clientHeight <= 0` のとき進捗を 0 と返すのが肝で、背の高いビューポートで文章が収まりきると `scrollTop / 0` が「読み終えた」と読めて1文字も読まないうちに飛ぶ。ホイールは `stopPropagation` だけで `preventDefault` はしない（ここでの既定動作こそがスクロール）。下端はスクロールバーではなく CSS マスクでフェードさせ、閉じの一文が霞まないよう本文側に `pb-14` を持たせて逃がしている。
- **省電力**: 詳細ページがキャンバスを覆っている間は `frameloop="demand"` に切り替え、毎秒1回だけ描画する。
- **URL**: 開いているセクションをハッシュ（`#products` 等）に反映し、戻るボタンとリンク共有に対応。ただしセクションの中身はクライアント描画のため、プリレンダーされた HTML には含まれない。

## テスト
- **Vitest**（node環境）。React も three.js も含まない純粋ロジックのみを対象にしているため、DOMもレンダラも不要で全体が1秒未満で走る。
- 対象: カメラの座標計算と飛行の補間（`3d/worldLayout.ts`）、紙吹雪のシミュレーション（`3d/confetti.ts`）、ジオラマの時計（`3d/sceneClock.ts`）、決定論的ハッシュ（`3d/voxel/rng.ts`）、制作実績のフィルタ（`sections/products/catalog.ts`）、プロジェクトデータの言語解決（`data/types.ts`）、URL の解釈（`sectionUrl.ts`）、詳細ページの退場方向（`detailSheet.ts`）、カードのホイール送り（`cardWheel.ts`）、自己紹介の読了判定（`aboutScroll.ts`）。
- 新しいテストは**変異テストで検証する運用**にしている。意図的なバグを仕込んで落ちることを確認しないと、緑であることに意味がないため。
